## K. NotionAdapter Mapping Verification
**IDENTIFIED ISSUE: Tool Mapping Mismatch**

The current NotionAdapter `_TOOL_MAPPING` expects:
```python
_TOOL_MAPPING = {
    "search_pages": ["notion-search", "search_pages"],
    "get_page": ["notion-fetch", "get_page"],
    "create_page": ["notion-create-pages", "create_page"],
    "update_page": ["notion-update-page", "update_page"],
    "query_database": ["notion-query-data-sources", "query_database"],
}
```

But the actual official server provides:
- Search: `API-post-search` (not `notion-search`)
- Get Page: `API-retrieve-a-page` or `API-retrieve-page-markdown` (not `notion-fetch`)
- Create Page: `API-post-page` (matches expectation)
- Update Page: `API-patch-page` or `API-update-page-markdown` (not `notion-update-page`)
- Query Database: `API-query-data-source` (not `notion-query-data-sources`)

This mismatch would cause the NotionAdapter's dynamic tool discovery to:
1. Fail to find expected tool names in server response
2. Fall back to legacy mock server names
3. Attempt to call non-existent tools on the official server
4. Result in tool call failures
