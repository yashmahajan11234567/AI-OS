# Part 12.11: JSON Schema Architecture

## Overview
This document defines the canonical JSON schemas for all core components of the AI-OS architecture. These schemas ensure type safety, interoperability, and evolution governance across agent interactions, workflows, and system state.

## Schema Governance
- **Registry Location**: `schemas/` directory in the repository
- **Versioning**: Semantic Versioning (MAJOR.MINOR.PATCH)
- **Compatibility Policy**: 
  - BACKWARD: New schemas must accept all valid instances of previous MINOR/PATCH versions
  - FORWARD: Previous schemas must ignore unknown fields in new instances
  - BREAKING: Requires MAJOR version increment and migration strategy
- **Extension Points**: All schemas include `$schema`, `version`, and `extensions` objects for vendor-specific additions
- **Validation Lifecycle**: 
  1. Syntax validation (JSON Schema Draft 07)
  2. Semantic validation (custom constraints)
  3. Business rule validation (context-dependent)
- **Conformance Requirements**: 
  - All producers MUST validate against latest schema version
  - All consumers MUST be tolerant of unknown fields (forward compatibility)
  - Extensions MUST use prefixed namespacing to avoid collisions

## Schema Evolution
- **Lifecycle Stages**: 
  1. DRAFT (experimental, no stability guarantees)
  2. STABLE (backward compatible changes only)
  3. DEPRECATED (supported for 2 minor versions)
  4. OBSOLETE (removed after deprecation period)
- **Migration Strategy**: 
  - Provide translation layers between adjacent versions
  - Document breaking changes in migration guides
  - Maintain compatibility shims for 2 versions post-deprecation
- **Registry Procedures**: 
  - New schemas require review by Architecture Council
  - Changes to STABLE schemas require 2-week comment period
  - All versions archived indefinitely in `schemas/archive/`

## Component Schemas

### Agent Descriptor
**Purpose**: Defines agent capabilities, interface, and metadata for registration and discovery.

**Required Fields**:
- `agentId`: string (UUID format)
- `name`: string (1-100 chars)
- `version`: string (semver)
- `capabilities`: array of Capability Descriptor references
- `entrypoint`: string (valid URI or module path)
- `securityLevel`: enum (`sandboxed`, `restricted`, `privileged`)

**Optional Fields**:
- `description`: string (max 500 chars)
- `tags`: array of strings (max 20 tags, each 1-50 chars)
- `extensions`: object (vendor-specific extensions)
- `documentation`: string (URI)
- `maintainer`: object (name, email, URI)

**Constraints**:
- `agentId` must be globally unique
- `version` must comply with semver.org
- `entrypoint` must be resolvable in agent runtime
- At least one capability required

**Validation Rules**:
- No duplicate capability references
- `tags` must be lowercase alphanumeric with hyphens
- `securityLevel` determines allowed API access

**JSON Example**:
```json
{
  "agentId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "name": "document-processor",
  "version": "1.2.0",
  "description": "Processes and extracts metadata from documentos",
  "tags": ["nlp", "document-analysis"],
  "capabilities": [
    {"capabilityId": "text-extraction-v1", "version": "1.0"},
    {"capabilityId": "summarization-v2", "version": "2.1"}
  ],
  "entrypoint": "agents/document-processor/index.js",
  "securityLevel": "restricted",
  "extensions": {
    "vendor-specific": {"timeoutMs": 5000}
  }
}
```

**Versioning**: Increment MINOR for new capabilities, PATCH for bug fixes, MAJOR for breaking interface changes.

**Compatibility**: Consumers should validate against declared `version` range.

**Extension Points**: `extensions` object for vendor-specific metadata.

**Cross References**: 
- References `Capability Descriptor` by `capabilityId`
- Used in `Agent Registration` and `Discovery Response`

### Capability Descriptor
**Purpose**: Defines a discrete unit of functionality an agent can perform.

**Required Fields**:
- `capabilityId`: string (UUID format)
- `name`: string (1-100 chars)
- `version`: string (semver)
- `inputSchema`: object (JSON Schema for inputs)
- `outputSchema`: object (JSON Schema for outputs)
- `executionModel`: enum (`synchronous`, `asynchronous`, `streaming`)

**Optional Fields**:
- `description`: string (max 500 chars)
- `tags`: array of strings
- `extensions`: object
- `timeoutMs`: integer (>0)
- `retryPolicy`: object (maxAttempts, backoffMs)
- `resourceRequirements`: object (cpu, memory, disk)

**Constraints**:
- `capabilityId` globally unique
- Schemas must be valid JSON Schema Draft 07
- `executionModel` determines interaction pattern

**Validation Rules**:
- Input/output schemas must not contain circular references
- `timeoutMs` must be positive integer
- Resource requirements non-negative

**JSON Example**:
```json
{
  "capabilityId": "f8e7d6c5-b4a3-2109-f8e7-d6c5b4a32109",
  "name": "text-summarization",
  "version": "2.1.0",
  "description": "Generates concise summaries of text documents",
  "tags": ["nlp", "summarization"],
  "inputSchema": {
    "type": "object",
    "properties": {
      "text": {"type": "string", "maxLength": 100000},
      "maxLength": {"type": "integer", "minimum": 10, "maximum": 500}
    },
    "required": ["text"]
  },
  "outputSchema": {
    "type": "object",
    "properties": {
      "summary": {"type": "string"},
      "confidence": {"type": "number", "minimum": 0, "maximum": 1}
    },
    "required": ["summary"]
  },
  "executionModel": "synchronous",
  "timeoutMs": 30000,
  "resourceRequirements": {"cpu": 2, "memoryMB": 512}
}
```

**Versioning**: Follows semver; breaking changes to schemas increment MAJOR.

**Compatibility**: Consumers adapt to schema changes via version negotiation.

**Extension Points**: `extensions` for capability-specific metadata.

**Cross References**: 
- Referenced by `Agent Descriptor`
- Used in `Delegation` and `Task` definitions

### Agent Registration
**Purpose**: Message sent by agents to announce availability to the directory service.

**Required Fields**:
- `agentDescriptor`: Agent Descriptor object
- `endpoint`: string (valid network address)
- `timestamp`: string (ISO 8601 UTC)
- `nonce`: string (cryptographically random, 32+ bytes base64url)

**Optional Fields**:
- `healthCheckUrl`: string (URI)
- `metadata`: object (deployment-specific info)
- `extensions`: object

**Constraints**:
- `endpoint` must be reachable from directory service
- `timestamp` within 5 minutes of server time
- `nonce` must be unique per registration

**Validation Rules**:
- Cryptographic signature verification (if securityLevel > sandboxed)
- Endpoint connectivity check (optional)
- Duplicate agentId handling per policy

**JSON Example**:
```json
{
  "agentDescriptor": {
    "agentId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
    "name": "document-processor",
    "version": "1.2.0",
    "capabilities": [{"capabilityId": "text-extraction-v1", "version": "1.0"}],
    "entrypoint": "agents/document-processor/index.js",
    "securityLevel": "restricted"
  },
  "endpoint": "ws://agent-node-42.internal:8080/ws",
  "timestamp": "2026-08-08T14:30:00Z",
  "nonce": "X9zZ2pQ8rTcVuBsN",
  "healthCheckUrl": "http://agent-node-42.internal:8080/health",
  "metadata": {
    "instanceId": "i-0a1b2c3d4e5f6g7h8",
    "region": "us-west-2"
  }
}
```

**Versioning**: Must match Agent Descriptor version.

**Compatibility**: Directory service supports multiple versions via content negotiation.

**Extension Points**: `metadata` and `extensions` for deployment specifics.

**Cross References**: 
- Contains `Agent Descriptor`
- Responses use `Discovery Response`

### Discovery Response
**Purpose**: Response from directory service containing matching agents.

**Required Fields**:
- `requestId`: string (matches discovery request)
- `timestamp`: string (ISO 8601 UTC)
- `agents`: array of Agent Descriptor objects
- `totalCount`: integer (≥0)

**Optional Fields**:
- `extensions`: object
- `truncated`: boolean (if results paginated)
- `continuationToken`: string (for pagination)

**Constraints**:
- `totalCount` equals actual matches (if not truncated)
- `agents` length ≤ page size (if paginated)

**Validation Rules**:
- All agents must be currently registered and healthy
- No duplicate agentId in response
- Timestamp within service SLA

**JSON Example**:
```json
{
  "requestId": "disc-req-7890",
  "timestamp": "2026-08-08T14:30:05Z",
  "agents": [
    {
      "agentId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
      "name": "document-processor",
      "version": "1.2.0",
      "capabilities": [{"capabilityId": "text-extraction-v1", "version": "1.0"}],
      "entrypoint": "agents/document-processor/index.js",
      "securityLevel": "restricted"
    }
  ],
  "totalCount": 1,
  "truncated": false
}
```

**Versioning**: Independent; reflects directory service API version.

**Compatibility**: Consumers should handle pagination and truncation.

**Extension Points**: `extensions` for service-specific metadata.

**Cross References**: 
- Contains `Agent Descriptor` array
- Request corresponds to discovery query (not formally schematized here)

### Workflow
**Purpose**: Defines a directed acyclic graph of tasks with dependencies and execution policies.

**Required Fields**:
- `workflowId`: string (UUID format)
- `version`: string (semver)
- `tasks`: array of Task objects (≥1)
- `dependencies`: object mapping taskId to array of dependent taskIds
- `entryPoints`: array of taskIds (nodes with no incoming dependencies)

**Optional Fields**:
- `name`: string (1-200 chars)
- `description`: string (max 1000 chars)
- `tags`: array of strings
- `extensions`: object
- `timeoutMs`: integer (>0)
- `retryPolicy`: object
- `schedulingPolicy`: enum (`parallel`, `sequential`, `priority-based`)
- `variables`: object (workflow-scoped variables)

**Constraints**:
- Graph must be acyclic
- All `dependencies` taskIds must exist in `tasks`
- `entryPoints` must be non-empty if tasks exist
- No circular dependencies

**Validation Rules**:
- Topological sort must succeed
- Task references valid
- Variables must have defined types if used

**JSON Example**:
```json
{
  "workflowId": "c3d4e5f6-a7b8-9012-c3d4-e5f6a7b89012",
  "version": "1.0.0",
  "name": "document-processing-pipeline",
  "description": "Extract, summarize, and classify documents",
  "tasks": [
    {
      "taskId": "extract-text",
      "name": "Extract Text",
      "capabilityReference": {"capabilityId": "text-extraction-v1", "version": "1.0"},
      "inputMapping": {"text": "$.document.content"},
      "outputMapping": {"extractedText": "$.text"}
    },
    {
      "taskId": "summarize",
      "name": "Summarize",
      "capabilityReference": {"capabilityId": "summarization-v2", "version": "2.1"},
      "inputMapping": {"text": "$.extract-text.extractedText"},
      "outputMapping": {"summary": "$.summary"}
    }
  ],
  "dependencies": {
    "extract-text": [],
    "summarize": ["extract-text"]
  },
  "entryPoints": ["extract-text"],
  "schedulingPolicy": "parallel",
  "timeoutMs": 300000
}
```

**Versioning**: MINOR for new tasks/features, PATCH for fixes, MAJOR for breaking DAG changes.

**Compatibility**: Consumers must handle additional tasks and dependency relaxations.

**Extension Points**: `extensions` for workflow-engine specific properties.

**Cross References**: 
- Contains `Task` objects
- References `Capability Descriptor` via `capabilityReference`
- Instantiated as `Workflow Execution` state

### Task
**Purpose**: Atomic unit of work within a workflow, referencing a capability.

**Required Fields**:
- `taskId`: string (unique within workflow)
- `name`: string (1-100 chars)
- `capabilityReference`: object (capabilityId + version)
- `inputMapping`: object (JSONPath expressions)
- `outputMapping`: object (JSONPath expressions)

**Optional Fields**:
- `description`: string (max 500 chars)
- `extensions`: object
- `timeoutMs`: integer (>0, overrides workflow)
- `retryPolicy`: object
- `variables`: object (task-scoped variables)
- `condition`: string (JSONPath boolean expression)

**Constraints**:
- `capabilityReference` must resolve to registered capability
- Mapping expressions must be valid JSONPath
- `taskId` unique within workflow

**Validation Rules**:
- Input/output schemas compatibility checked at workflow validation
- Condition must evaluate to boolean
- No dangerous JSONPath expressions (e.g., script execution)

**JSON Example**:
```json
{
  "taskId": "summarize",
  "name": "Summarize Document",
  "capabilityReference": {
    "capabilityId": "summarization-v2",
    "version": "2.1"
  },
  "description": "Generate summary from extracted text",
  "inputMapping": {
    "text": "$.extract-text.output.extractedText",
    "maxLength": 200
  },
  "outputMapping": {
    "summary": "$.result.summary",
    "confidence": "$.result.confidence"
  },
  "timeoutMs": 60000,
  "condition": "$.extract-text.status == 'success'"
}
```

**Versioning**: Inherits workflow version; task-level changes require workflow version bump.

**Compatibility**: Consumers should ignore unknown mapping fields.

**Extension Points**: `extensions` for task-execution hints.

**Cross References**: 
- References `Capability Descriptor`
- Composed within `Workflow`
- Instantiated as `Task Execution` state

### Delegation
**Purpose**: Request for one agent to invoke a capability on another agent's behalf.

**Required Fields**:
- `delegationId`: string (UUID format)
- `timestamp`: string (ISO 8601 UTC)
- `delegatorId`: string (agentId of requesting agent)
- `delegateeId`: string (agentId of target agent)
- `capabilityId`: string (matches delegatee's capability)
- `version`: string (requested capability version)
- `payload`: object (valid per capability's inputSchema)
- `nonce`: string (cryptographically random, 32+ bytes base64url)

**Optional Fields**:
- `correlationId`: string (for tracing related operations)
- `extensions`: object
- `timeoutMs`: integer (>0)
- `priority`: integer (1-10, higher = more urgent)
- `ttlMs`: integer (>0, time-to-live for delegation)

**Constraints**:
- `delegatorId` ��� � � ≠ `delegateeId` (self-delegation handled locally)
- `capabilityId` must exist in delegatee's registered capabilities
- `version` must satisfy delegatee's version range for capability
- `nonce` unique per delegation from delegator

**Validation Rules**:
- Payload validates against capability's inputSchema
- Signature verification if security requirements mandate
- Delegator authorized for capability (policy-dependent)
- Delegator/delegatee must be currently registered

**JSON Example**:
```json
{
  "delegationId": "d4e5f6a7-b8c9-0123-d4e5-f6a7b8c90123",
  "timestamp": "2026-08-08T14:30:10Z",
  "delegatorId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "delegateeId": "b2c3d4e5-f6a7-8901-b2c3-d4e5f6a7b8c9",
  "capabilityId": "summarization-v2",
  "version": "2.1.0",
  "payload": {
    "text": "The quick brown fox jumps over the lazy dog...",
    "maxLength": 150
  },
  "nonce": "K2lM5nOpQrStUvWxYz",
  "correlationId": "trace-abc-123",
  "timeoutMs": 45000,
  "priority": 7,
  "ttlMs": 300000
}
```

**Versioning**: Delegation proto version separate; capability version negotiated.

**Compatibility**: Delegator handles version negotiation fallback.

**Extension Points**: `extensions` for delegation policy metadata.

**Cross References**: 
- References `Agent Descriptor` (ids)
- References `Capability Descriptor` (id/version)
- Results in `Task Execution` or direct response
- Audited via `Audit Record`

### Council
**Purpose**: Represents the AI-OS Architecture Council member and voting record.

**Required Fields**:
- `councilMemberId`: string (UUID format)
- `name`: string (1-100 chars)
- `organization`: string (1-200 chars)
- `termStart`: string (ISO 8601 date)
- `termEnd`: string (ISO 8601 date, > termStart)
- `votes`: array of Vote objects

**Optional Fields**:
- `title`: string (e.g., "Chair", "Secretary")
- `extensions`: object
- `contact`: object (email, URI)

**Constraints**:
- `termEnd` after `termStart`
- No overlapping terms for same organization (policy)
- `votes` must reference valid proposals

**Validation Rules**:
- Cryptographic identity verification
- Term limits enforced (max 2 consecutive terms)
- Vote timestamps within term period

**JSON Example**:
```json
{
  "councilMemberId": "e5f6a7b8-c9d0-1234-e5f6-a7b8c9d01234",
  "name": "Dr. Elena Rodriguez",
  "organization": "Tech Standards Consortium",
  "title": "Chair",
  "termStart": "2025-01-01",
  "termEnd": "2027-01-01",
  "contact": {"email": "elena@example.org", "uri": "https://example.org/staff/erodriguez"},
  "votes": [
    {
      "voteId": "vote-001",
      "proposalId": "prop-schema-v2",
      "choice": "APPROVE",
      "timestamp": "2026-05-15T09:30:00Z",
      "reasoning": "Addresses critical security gaps in v1"
    }
  ]
}
```

**Versioning**: Council membership independent of schema versions.

**Compatibility**: Historical records preserved unchanged.

**Extension Points**: `extensions` for role-specific attributes.

**Cross References**: 
- Contains `Vote` objects
- Votes reference proposals (external to schema set)

### Vote
**Purpose**: Individual voting record on an architecture proposal.

**Required Fields**:
- `voteId`: string (UUID format)
- `proposalId`: string (references external proposal system)
- `choice`: enum (`APPROVE`, `REJECT`, `ABSTAIN`)
- `timestamp`: string (ISO 8601 UTC)
- `reasoning`: string (max 2000 chars)

**Optional Fields**:
- `extensions`: object
- `alternativeId`: string (if proposing amendment)

**Constraints**:
- `choice` must be valid enum value
- `timestamp` during active voting period
- `reasoning` required for non-abstain votes

**Validation Rules**:
- Proposal must be in votable state
- Member must be eligible to vote on proposal
- No duplicate voteId per member/proposal

**JSON Example**:
```json
{
  "voteId": "f6a7b8c9-d0e1-2345-f6a7-b8c9d0e12345",
  "proposalId": "prop-schema-v2",
  "choice": "APPROVE",
  "timestamp": "2026-05-15T09:30:00Z",
  "reasoning": "Addresses critical security gaps in v1 while maintaining backward compatibility.",
  "alternativeId": null
}
```

**Versioning**: Vote record version independent.

**Compatibility**: Historical votes never altered.

**Extension Points**: `extensions` for voting context (e.g., meeting ID).

**Cross References**: 
- Contained within `Council` member record
- References external proposal tracking system

### Decision
**Purpose**: Finalized outcome of an architecture proposal after council voting.

**Required Fields**:
- `decisionId`: string (UUID format)
- `proposalId`: string (matches voted proposal)
- `outcome`: enum (`ADOPTED`, `REJECTED`, `DEFERRED`)
- `timestamp`: string (ISO 8601 UTC)
- `effectiveDate`: string (ISO 8601 date)
- `supportedBy`: array of councilMemberId strings (≥ quorum)

**Optional Fields**:
- `description`: string (max 1000 chars)
- `extensions`: object
- `relatedDecisions`: array of decisionId strings

**Constraints**:
- `outcome` determines `supportedBy` requirements:
  - `ADOPTED`: ≥2/3 of seated council
  - `REJECTED`: ≥1/3 opposition
  - `DEFERRED`: < quorum for decision
- `effectiveDate` ≥ `timestamp`
- `supportedBy` members must have voted accordingly

**Validation Rules**:
- Decision follows valid voting record
- Effective date allows for transition period
- Related decisions form valid change history

**JSON Example**:
```json
{
  "decisionId": "g7h8i9j0-e1f2-3456-g7h8-i9j0k1l2m3n4",
  "proposalId": "prop-schema-v2",
  "outcome": "ADOPTED",
  "timestamp": "2026-05-20T16:00:00Z",
  "effectiveDate": "2026-06-01",
  "description": "Adopts JSON Schema v2 for all inter-agent communication, introducing capability versioning and delegation security enhancements.",
  "supportedBy": [
    "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
    "b2c3d4e5-f6a7-8901-b2c3-d4e5f6a7b8c9",
    "c3d4e5f6-a7b8-9012-c3d4-e5f6a7b89012",
    "d4e5f6a7-b8c9-0123-d4e5-f6a7b8c90123",
    "e5f6a7b8-c9d0-1234-e5f6-a7b8c9d01234",
    "f6a7b8c9-d0e1-2345-f6a7-b8c9d0e12345"
  ],
  "relatedDecisions": ["dec-legacy-v1"]
}
```

**Versioning**: Decision effective date triggers schema version rollout.

**Compatibility**: Documents binding architectural commitments.

**Extension Points**: `extensions` for implementation guidance.

**Cross References**: 
- References `Council` member IDs
- Records outcome of `Vote` aggregation
- Governs schema `Versioning` and `Compatibility` policies

### Shared Context
**Purpose**: Mutable state shared between agents participating in a collaboration.

**Required Fields**:
- `contextId`: string (UUID format)
- `version`: integer (≥1, monotonically increasing)
- `timestamp`: string (ISO 8601 UTC)
- `data`: object (arbitrary JSON-serializable state)
- `participants`: array of agentId strings (≥1)

**Optional Fields**:
- `name`: string (1-100 chars)
- `description`: string (max 500 chars)
- `extensions`: object
- `ttlMs`: integer (>0, time-to-live)
- `accessPolicy`: object (read/write permissions per participant)

**Constraints**:
- `version` increments on every mutation
- `timestamp` updates on every mutation
- `participants` must be currently registered agents
- `data` size limited by implementation (typically 1MB)

**Validation Rules**:
- Only participants can mutate (enforced by context service)
- Version must be exactly one greater than previous for linear history
- No circular context references (prevents deadlock)

**JSON Example**:
```json
{
  "contextId": "h8i9j0k1-l2m3-4567-h8i9-j0k1l2m34567",
  "name": "document-review-session-42",
  "description": "Shared state for collaborative document review",
  "version": 5,
  "timestamp": "2026-08-08T14:35:22Z",
  "data": {
    "documentId": "doc-98765",
    "currentReviewer": "agent-xyz",
    "comments": [
      {"id": "c1", "agentId": "agent-abc", "text": "Clarify section 3.2", "resolved": false}
    ],
    "decision": "pending"
  },
  "participants": ["agent-abc", "agent-def", "agent-xyz"],
  "ttlMs": 3600000,
  "accessPolicy": {
    "agent-abc": {"read": true, "write": true},
    "agent-def": {"read": true, "write": false},
    "agent-xyz": {"read": true, "write": true}
  }
}
```

**Versioning**: Context version independent of schema; schema version governs envelope.

**Compatibility**: Consumers tolerate additional data fields.

**Extension Points**: `extensions` for context service metadata.

**Cross References**: 
- Referenced by `Context Snapshot`
- Mutated via `Delegation` and `Task` side effects
- Related to `Message Envelope` for notifications

### Knowledge Object
**Purpose**: Immutable unit of knowledge or information within the AI-OS knowledge base.

**Required Fields**:
- `knowledgeId`: string (UUID format)
- `contentType`: string (MIME type, e.g., "text/markdown", "application/json")
- `content`: string (base64-encoded if binary, otherwise UTF-8 text)
- `createdAt`: string (ISO 8601 UTC)
- `createdBy`: string (agentId)
- `checksum`: string (SHA-256 hex digest of content)

**Optional Fields**:
- `title`: string (1-200 chars)
- `description`: string (max 500 chars)
- `tags`: array of strings
- `extensions`: object
- `source`: string (URI or citation)
- `relatedKnowledge`: array of knowledgeId strings
- `accessLevel`: enum (`public`, `restricted`, `confidential`)

**Constraints**:
- `content` must match `checksum`
- `createdAt` cannot be in future
- `createdBy` must be registered agent at time of creation
- `accessLevel` determines visibility rules

**Validation Rules**:
- Content type determines encoding expectations
- Tags must be lowercase alphanumeric with hyphens
- KnowledgeId must be globally unique
- Immutable after creation (any change requires new knowledgeId)

**JSON Example**:
```json
{
  "knowledgeId": "i9j0k1l2-m3n4-5678-i9j0-k1l2m3n45678",
  "title": "JSON Schema v2 Migration Guide",
  "contentType": "text/markdown",
  "content": "# Migration Guide\\n\\nThis document describes...",
  "description": "Step-by-step guide for upgrading from schema v1 to v2",
  "tags": ["schema", "migration", "guide"],
  "createdAt": "2026-05-22T10:00:00Z",
  "createdBy": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "checksum": "a3f1c2e4b5d6f7g8h9i0j1k2l3m4n5o6p7q8r9s0t1u2v3w4x5y6z7a8b9c0d1e2",
  "source": "internal:architecture-council/minutes/2026-05-20",
  "accessLevel": "public",
  "relatedKnowledge": ["kg-legacy-schema-v1"]
}
```

**Versioning**: Knowledge objects immutable; versioning via new objects.

**Compatibility**: Consumers handle unknown content types gracefully.

**Extension Points**: `extensions` for domain-specific metadata (e.g., scientific annotations).

**Cross References**: 
- Referenced by `Shared Context` (as knowledge pointers)
- Used in `Task` inputs/outputs
- Related via `relatedKnowledge` for knowledge graphs

### Context Snapshot
**Purpose**: Immutable copy of Shared Context at a point in time for auditing or rollback.

**Required Fields**:
- `snapshotId`: string (UUID format)
- `contextId`: string (matches existing Shared Context)
- `version`: integer (matches context version at snapshot time)
- `timestamp`: string (ISO 8601 UTC)
- `data`: object (exact copy of context.data at snapshot time)
- `createdBy`: string (agentId that initiated snapshot)

**Optional Fields**:
- `reason`: string (max 200 chars, e.g., "pre-migration-backup")
- `extensions`: object
- `participants`: array of agentId strings (context participants at snapshot time)

**Constraints**:
- `version` must be ≥1 and ≤ current context version
- `timestamp` must be ≥ context creation and ≤ now
- `data` must match context state at (`contextId`, `version`)
- `createdBy` must be context participant or system agent

**Validation Rules**:
- Cryptographic proof of context state (if required by policy)
- No future timestamps
- SnapshotId unique per context

**JSON Example**:
```json
{
  "snapshotId": "j0k1l2m3-n4o5-6789-j0k1-l2m345678901",
  "contextId": "h8i9j0k1-l2m3-4567-h8i9-j0k1l2m34567",
  "version": 3,
  "timestamp": "2026-08-08T14:30:00Z",
  "data": {
    "documentId": "doc-98765",
    "currentReviewer": "agent-def",
    "comments": [
      {"id": "c1", "agentId": "agent-abc", "text": "Clarify section 3.2", "resolved": false}
    ],
    "decision": "pending"
  },
  "createdBy": "agent-abc",
  "reason": "Pre-summarization backup",
  "participants": ["agent-abc", "agent-def"]
}
```

**Versioning**: Snapshot format version independent; context version captured.

**Compatibility**: Snapshots readable by any context service version.

**Extension Points**: `extensions` for snapshot purpose metadata.

**Cross References**: 
- References `Shared Context` (id/version)
- Used in audit trails and disaster recovery
- Related to `Runtime State` for system checkpoints

### Message Envelope
**Purpose**: Standard wrapper for all inter-agent communications.

**Required Fields**:
- `messageId`: string (UUID format)
- `timestamp`: string (ISO 8601 UTC)
- `senderId`: string (agentId)
- `recipientId`: string (agentId or "broadcast")
- `messageType`: string (e.g., "delegation-request", "task-result", "event")
- `version`: string (envelope schema version)
- `payload`: object (valid per messageType specification)
- `nonce`: string (cryptographically random, 32+ bytes base64url)

**Optional Fields**:
- `correlationId`: string (for tracing message chains)
- `extensions`: object
- `priority`: integer (1-5, higher = more urgent)
- `ttlMs`: integer (>0)
- `routingHints`: object (service-specific routing info)

**Constraints**:
- `senderId` must be currently registered agent
- `recipientId` must be valid agentId or "broadcast"
- `messageType` determines expected payload structure
- `nonce` unique per sender within time window
- `timestamp` within clock skew tolerance

**Validation Rules**:
- Payload validates against messageType schema
- Signature verification if security policy requires
- Recipient authorized for messageType from sender
- No envelope spoofing (cryptographic binding to sender)

**JSON Example**:
```json
{
  "messageId": "k1l2m3n4-o5p6-7890-k1l2-m3n456789012",
  "timestamp": "2026-08-08T14:30:15Z",
  "senderId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "recipientId": "b2c3d4e5-f6a7-8901-b2c3-d4e5f6a7b8c9",
  "messageType": "delegation-request",
  "version": "1.0",
  "payload": {
    "delegationId": "d4e5f6a7-b8c9-0123-d4e5-f6a7b8c90123",
    "capabilityId": "summarization-v2",
    "version": "2.1.0",
    "payload": {"text": "Sample text...", "maxLength": 150}
  },
  "nonce": "L3mN4o5p6Q7r8S9t0U1v2W3x4Y5z6A7b",
  "correlationId": "trace-abc-123",
  "priority": 3,
  "ttlMs": 60000
}
```

**Versioning**: Envelope version independent; governs security and routing features.

**Compatibility**: Consumers must tolerate unknown extensions and fields.

**Extension Points**: `extensions` for middleware (tracing, security, QoS).

**Cross References**: 
- Contains `Delegation`, `Task`, `Event`, etc. as payload
- Used by all inter-agent communication patterns
- Related to `Audit Record` for message logging

### Event
**Purpose**: Notification of something that has happened within the system.

**Required Fields**:
- `eventId`: string (UUID format)
- `timestamp`: string (ISO 8601 UTC)
- `sourceId`: string (agentId or system component)
- `eventType`: string (e.g., "agent-registered", "task-completed", "health-check-failed")
- `version`: string (event schema version)
- `data`: object (valid per eventType specification)

**Optional Fields**:
- `correlationId`: string (for tracing related events)
- `extensions`: object
- `severity`: enum (`debug`, `info`, `warning`, `error`, `critical`)
- `ttlMs`: integer (>0)
- `targets`: array of recipient specifications (for multicast)

**Constraints**:
- `sourceId` must be valid entity in system
- `eventType` determines expected data structure
- `timestamp` cannot be in future
- Severity levels follow standard logging semantics

**Validation Rules**:
- Data validates against eventType schema
- No internal system leakage in data (security review)
- EventType must be registered in event catalog
- CorrelationId links related events for tracing

**JSON Example**:

**Compatibility**: Consumers handle unknown eventTypes gracefully (log and drop).

**Extension Points**: `extensions` for domain-specific event data (e.g., ML model metrics).

**Cross References**: 
- Published via `Message Envelope`
- May trigger `Shared Context` updates
- Audited via `Audit Record`

### Scheduler Request
**Purpose**: Request to execute a task or workflow at a specified time or interval.

**Required Fields**:
- `requestId`: string (UUID format)
- `timestamp`: string (ISO 8601 UTC)
- `requesterId`: string (agentId)
- `targetId`: string (agentId for delegation, or workflowId)
- `targetType`: enum (`agent-capability`, `workflow`)
- `trigger`: object (defines when to execute)
- `payload`: object (valid per target specification)

**Optional Fields**:
- `name`: string (1-100 chars)
- `description`: string (max 500 chars)
- `extensions`: object
- `priority`: integer (1-10)
- `maxInstances`: integer (≥1, max concurrent executions)
- `catchup`: boolean (run missed intervals on startup)

**Constraints**:
- `targetType` determines interpretation of `targetId`
- `trigger` must be valid cron expression or interval specification
- `payload` must satisfy target's input requirements
- `requesterId` authorized to schedule `targetId`

**Validation Rules**:
- Trigger syntax validated (cron library or ISO 8601 interval)
- Payload validates against target schema
- No scheduling conflicts with existing high-priority jobs
- Requester has appropriate permissions

**JSON Example**:
```json
{
  "requestId": "m3n4o5p6-q7r8-9012-m3n4-o5p678901234",
  "timestamp": "2026-08-08T14:30:25Z",
  "requesterId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "targetId": "c3d4e5f6-a7b8-9012-c3d4-e5f6a7b89012",
  "targetType": "workflow",
  "name": "nightly-document-summarization",
  "description": "Process new documents added after 2AM",
  "trigger": {"cron": "0 2 * * *", "timezone": "UTC"},
  "payload": {
    "workflowId": "c3d4e5f6-a7b8-9012-c3d4-e5f6a7b89012",
    "parameters": {"minFileSize": 1024}
  },
  "priority": 5,
  "maxInstances": 1,
  "catchup": false
}
```

**Versioning**: Request format version independent; trigger syntax stable.

**Compatibility**: Scheduler service handles version negotiation for targets.

**Extension Points**: `extensions` for scheduler-specific policies (e.g., resource quotas).

**Cross References**: 
- References `Agent Descriptor` (for capability targets)
- References `Workflow` (for workflow targets)
- Results in `Delegation` or `Workflow Execution`
- Audited via `Audit Record`

**Validation Rules**:

### Audit Record
**Purpose**: Immutable log of security-relevant and operational events for compliance and forensics.

**Required Fields**:
- `recordId`: string (UUID format)
- `timestamp`: string (ISO 8601 UTC)
- `eventType`: string (e.g., "delegation-approved", "knowledge-accessed", "config-changed")
- `actorId`: string (agentId, userId, or system component)
- `actorType`: enum (`agent`, `user`, `system`)
- `targetId`: string (object or resource identifier)
- `targetType`: enum (`agent`, `workflow`, `task`, `knowledge`, `context`, `system`)
- `outcome`: enum (`success`, `failure`)
- `severity`: enum (`info`, `warning`, `error`, `critical`)
- `checksum`: string (SHA-256 hex of record excluding this field)

**Optional Fields**:
- `reason`: string (max 500 chars, explains outcome)
- `extensions`: object
- `correlationId`: string (for tracing related audit events)
- `sessionId`: string (if part of user session)
- `source`: string (IP address, hostname, or component)

**Constraints**:
- `actorType` determines valid `actorId` format
- `targetType` determines valid `targetId` format
- `checksum` must match recalculated value (tamper detection)
- `timestamp` cannot be in future
- `outcome` determines required fields (failure needs reason)

**Validation Rules**:
- Immutable after writing (write-once storage)
- No sensitive data in reason field (PII/credentials redacted)
- EventType must be registered in audit event catalog
- Retention period enforced by storage policy
- RecordId unique per reporting system

**JSON Example**:
```json
{
  "recordId": "r8s9t0u1-v2w3-4567-r8s9-t0u123456789",
  "timestamp": "2026-08-08T14:30:50Z",
  "eventType": "delegation-approved",
  "actorId": "a1b2c3d4-e5f6-7890-g1h2-i3j4k5l6m7n8",
  "actorType": "agent",
  "targetId": "d4e5f6a7-b8c9-0123-d4e5-f6a7b8c90123",
  "targetType": "delegation",
  "outcome": "success",
  "severity": "info",
  "reason": "Delegation from document-processor to summarizer approved based on capability match and policy",
  "correlationId": "trace-abc-123",
  "sessionId": "sess-user-42",
  "source": "agent-node-42.internal",
  "checksum": "c5d6e7f8g9h0i1j2k3l4m5n6o7p8q9r0s1t2u3v4w5x6y7z8a9b0c1d2e3f4g5"
}
```

**Versioning**: Audit record version independent; event types evolvable.

**Compatibility**: Historical records never altered; new types additive.

**Extension Points**: `extensions` for jurisdiction-specific fields (e.g., GDPR lawful basis).

**Cross References**: 
- Records all `Delegation`, `Task`, `Message Envelope` interactions
- Logs `Health Report` status changes and `Scheduler Request` creations
- Tracks `Knowledge Object` access and `Shared Context` mutations
- Documents `Security Metadata` enforcement and violations
- Feeds compliance reporting and SIEM systems
