## 14.13.1 Purpose and Scope

**Status:** EXISTING (context.md §0.4, §0.6; MEMORY.md §1, §2)

Part 14.13 is the final cross-reference and ADR summary for Part 14. Its purpose is to provide:

- a master cross-reference index across Part 14 documents and back to the authoritative source Parts;
- an ADR summary that records only what the permitted control files establish about ADRs;
- a controlled mapping of canonical conflicts (CONFLICT-01 … CONFLICT-07 and related event/registry conflicts);
- a cross-reference of GAPs, UNRES items, and UNSPECIFIED domains;
- a preservation record of RETRACTED architecture that must not be re-introduced as current;
- a final traceability matrix;
- explicit rules preventing future AI agents from making unsafe inferences.

**Scope boundary (EXISTING — MEMORY.md §2, context.md §1.3):** 14.13 does NOT:

- define new cross-references, ADRs, or integration patterns;
- resolve any source conflict;
- create a new GAP registry (it cross-references existing GAPs from the control files);
- create a new conflict registry (it cross-references existing conflicts from the control files);
- establish new architecture, technology, protocol, interface, event, schema, or security mechanism.

**Cross-referencing does not create authority** — see the CANONICAL AUTHORITY RULE (§14.13.2.5). A citation in 14.13 does not transfer authority from the cited source to this document, and does not promote a referenced concept to established architecture. Where a source is itself a non-authoritative document (e.g., a DRAFT ADR, a Part 14 chapter marked EMPTY, or a memory/continuity artifact), that status is preserved in the citation.

## 14.13.4 Source Authority and Verification

**Status:** DERIVED (context.md §0.3 Provenance Requirement; MEMORY.md §10, §12)

14.13 distinguishes five classes of information. This distinction is mandatory for safe consumption.

| Class | Definition | How 14.13 treats it |
|-------|------------|---------------------|
| 1. Directly verified control-file information | Present in one of the five permitted files (context.md, MEMORY.md, glossary.md, review-checklist.md, or README.md) | Presented with the control-file citation |
| 2. Broader-corpus references preserved from prior material | Referenced by the control files but the underlying document is outside the five-file boundary (e.g., adrs.md, source Parts 0–13) | Tagged **corpus-reference**; independence NOT claimed |
| 3. DERIVED interpretations | Logically implied by EXISTING statements | Inference path shown; labeled DERIVED |
| 4. UNSPECIFIED | Named in source but no detail provided | Labeled UNSPECIFIED; not invented |
| 5. Unresolved conflicts | Authoritative sources disagree | Labeled CONFLICT; preserved; escalated to ARB |

**CANONICAL VERIFICATION RULE (CVR):** 14.13 MUST NOT pretend that an unavailable source was independently verified. Every citation to a document outside the five-file boundary is marked corpus-reference, and the boundary is restated in §14.13.13. (EXISTING — MEMORY.md §10 rule 7.)

**Verification status vocabulary (used throughout this document):**

- **VERIFIED (control-file):** established by one of context.md / MEMORY.md / glossary.md / review-checklist.md / README.md, which were readable in the isolated terminal.
- **CORPUS-REFERENCE:** referenced by a control file, but the underlying document was outside the five-file boundary and was NOT independently re-verified here. Independence is not claimed.
- **UNSPECIFIED / UNVERIFIED:** the item is named but its content could not be established from available sources.

> **Correction:** Where the prior version implied independent verification of external files, that implication is removed. Legitimate existing traceability is retained but explicitly marked corpus-reference.

## 14.13.6 ADR Authority and Precedence

**Status:** EXISTING (context.md §0.2 rule 4; MEMORY.md §3.1 rule 4; review-checklist.md §1.2)

- An ADR does **not** automatically override another authoritative architecture source. An accepted/active ADR is authoritative only within its explicit decision and expiry conditions (context.md §0.2 rule 4).
- Later numbering does **not** automatically imply higher authority. ADR-016 does not outrank ADR-001 by number; P14-ADRs do not outrank Core ADRs.
- Conflicts between an ADR and a source Part MUST remain visible (context.md §0.6 Integrity Rule 3).
- ADR status matters: Active/Accepted ADRs are authoritative within scope; Draft ADRs (P13-ADR-*) are proposals only; Part 14 Integration Impact Records are cross-references, not decisions.
- RETRACTED ADR material (if any) MUST NOT be presented as current. (No RETRACTED ADR is established by the control files; this rule is stated preventively per MEMORY.md §6.)

No new precedence hierarchy is created by 14.13.

## 14.13.12 Cross-Reference Integrity Rules

**Status:** EXISTING (context.md §0.6 Integrity Rules 1–8; MEMORY.md §10; task §14.13.12)

The following rules bind every cross-reference in 14.13 and in Part 14 generally. Canonical rules CAR / CCR / CGUR / CRR / CVR are defined in §14.13.2.5, §14.13.7.1, §14.13.8.1, §14.13.9, §14.13.4 and are not re-stated at length here; they are referenced by number.

1. A reference does not imply adoption. Citing a source Part, ADR, or document does not make its content part of Part 14 architecture (CAR).
2. An ADR reference does not imply implementation. An ADR records a decision; it does not prove the mechanism exists in implemented architecture (glossary.md §1.3; MEMORY.md §10 rule 6).
3. A GAP reference does not imply resolution. Recording a GAP preserves the silence; it does not fill it (CGUR).
4. A conflict reference does not imply resolution. CONFLICT entries are preserved and escalated, not normalized (CCR).
5. A source citation does not transfer authority. The cited source remains authoritative within its domain; 14.13 gains nothing from citing it (CAR).
6. A DERIVED statement is not EXISTING. DERIVED requires an inference path; without it, the claim is invalid (MEMORY.md §10 rule 2).
7. A RETRACTED source is not current architecture. RETRACTED/CORRECTED claims are historical corrections only (CRR).
8. An unavailable source MUST NOT be presented as independently verified. Documents outside the five-file boundary are tagged corpus-reference (CVR).
9. No new architectural layer, component, manager, service, facade, governance component, interface, event, schema, protocol, or guarantee may be introduced (context.md §0.6 Integrity Rule 4; MEMORY.md §10 rule 9).
10. Status labels MUST be applied uniquely and correctly per the legend (context.md §0.6 Integrity Rule 1; review-checklist.md §6).
11. Provenance MUST be stated for every major claim; DERIVED claims MUST show inference path; ASSUMPTION claims MUST be flagged (context.md §0.6 Integrity Rules 2, 8).

**CRR:** RETRACTED material is historical only and MUST NOT be presented as current architecture. When a retraction log references a concept (e.g., "RPC architecture," "Universal Plugin Registry," "Topology Manager," "zero-trust/mTLS inference," "invented schema validation architecture"), that concept is REMOVED from the current AI-OS architecture. Any reference to a RETRACTED concept is for historical traceability only; it does NOT revive the architecture.

**Source fidelity safeguard:** Every claim in Part 14 that references a document outside the five permitted files (context.md, glossary.md, review-checklist.md, README.md, MEMORY.md) is marked **corpus-reference**. Independence is explicitly NOT claimed for these references. If the source material (e.g., adrs.md, interfaces.md, schemas.md, events.md, dependency-map.md, integrations.md) is NOT independently readable by the isolated terminal, the reference is preserved as corpus-reference. If the source material is read from within the five-file boundary, then the claim is marked **VERIFIED**.

**Cross-reference does not transfer authority:** A citation in 14.13 does NOT transfer authority from the cited source to this document, and does NOT promote a referenced concept to established architecture. Where a source is itself a non-authoritative document (e.g., a DRAFT ADR, a Part 14 chapter marked EMPTY, or a memory/continuity artifact), that status is preserved in the citation.
