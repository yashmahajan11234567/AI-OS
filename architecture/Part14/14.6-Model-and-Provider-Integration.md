## 1. Document Purpose and Position

**Status:** DERIVED

This chapter documents how **model inference** and **external model providers** integrate with the AI-OS platform, strictly from readable source-established architecture. It introduces no new Core Component, Core Manager, interface, event, schema, protocol, or guarantee.

The canonical architectural anchors established by the readable files are:

- `LLMManager` — one of the nine canonical Core Managers (`context.md §3.1`).
- `ModelRouter` — an **implementation-mapped manager name** that maps to the canonical Core Manager `LLMManager` (`context.md §3.1`).
- **Custom model providers** — a permitted extension point (`context.md §1.1` citing Part 00 §0.5.2; `context.md §14.2`; `context.md §15.1`).
- **Custom model providers MUST register in ModelRouter** — a stated extension-point requirement (`context.md §14.2` citing Part 00 §0.5.2; `MEMORY.md §14` identifies ADR-013 as the Extension Points ADR).

The integration also overlaps the **AuthN/AuthZ v1.0 conflict** (CONFLICT-03, `context.md §12.1`/`§15.3`; `MEMORY.md §5`) and the **Core Component naming conflict** (CONFLICT-01, `context.md §3.1`; `MEMORY.md §5`), both preserved below.

**Part 14 implication:** Every claim below is traceable to a readable source or is marked UNSPECIFIED (corpus-reference). Anything not so traceable is marked UNSPECIFIED.

## 3. Model vs Provider (central distinction)

**Status:** DERIVED (from `context.md §3.1`, `§14.2`, `§15.1`)

This chapter deliberately keeps two concepts distinct, per the task's central principle:

- **Model** — the model capability or artifact being used. A model is the *capability/artifact*, not the integration boundary through which it is reached.
- **Model Provider** — the system or integration boundary through which one or more models may be made available to AI-OS. Custom model providers are an explicit extension point (`context.md §1.1`, `§14.2`, `§15.1`).

A model is **not** automatically a provider. A provider is **not** automatically a model. The readable sources do not establish that a provider owns the underlying model, nor that a model is embedded in or served by a particular provider.

**DERIVED inference path:** `context.md §14.2` establishes "custom model providers" as a distinct extension-point class separate from the `LLMManager`/`ModelRouter` capability owner ⇒ model and provider are separable architectural concepts in AI-OS.

**Part 14 MUST NOT:** collapse "model" and "provider" into one entity; assume a 1:1 model↔provider mapping; or invent a canonical model registry, canonical provider catalog, or model-to-provider ownership relationship.
