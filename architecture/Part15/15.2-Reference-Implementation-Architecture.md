#### 5.4.3 Anti-Patterns to Avoid

The following patterns are direct violations of authoritative architecture and MUST NOT appear in implementation:

| Anti-Pattern | Why It Violates | What To Do Instead |
|-------------|----------------|-------------------|
| `service_a.method()` across service boundaries | Direct service-to-service calls bypass EventBus | Emit event; let ServiceBus route to consumer |
| `manager_a.method()` across manager boundaries | Direct manager-to-manager calls bypass EventBus | Emit event; let EventBus route to consumer |
| Instantiating Core Components outside HermesKernel | Violates kernel-exclusive ownership (INV-OWN-001) | HermesKernel constructs all Core Components |
| Mutating EventBus configuration after RUNNING | Configuration freeze invariant | Freeze ConfigurationManager before Core Managers init |
| Synchronous HTTP/gRPC for inter-component communication | Event-First Communication principle (Part 0 Principle 1) | All coordination via EventBus; transport adapters at system boundary |
| Hardcoded Core Component or Core Manager lists | CONFLICT-CC-01/CONFLICT-CM-01 preservation | Parameterize implementation; support superset or ARB-selected set |
| Multiple HermesKernel instances in one process | Singleton enforcement (Part 1 §1.8) | Singleton pattern with process-global guard |
| Implementing independent authorization in a Service | ABAC mandates SecurityManager as sole authority | All authorization MUST route through SecurityManager.authorize() |

#### 5.4.4 Implementation Pattern Guidance

The following patterns are aligned with authoritative architecture and are provided as guidance:

| Pattern | When To Use | Implementation Notes |
|---------|-------------|----------------------|
| **Singleton Accessor Pair** | Every kernel-owned singleton | `get_<component>()` / `set_<component>()` per Part 0 §0.3.2; initialized in Phase 0–3 for Core Components, Phase 4–8 for Core Managers |
| **Event-Driven State Machine** | Lifecycle transitions | Emit `KernelLifecycleEvent` before and after every state transition; LifecycleManager owns state machine |
| **Dependency Injection at Initialize** | Core Component initialization | Per CC-IR-002, dependency injection via `initialize(kernel)` parameters is PERMITTED during init; post-init, communication via EventBus only |
| **Topological Initialization Batches** | Service initialization | ServiceRegistry computes DAG; LifecycleManager executes parallel batches within dependency layers |
| **Consequence Event Emission** | Failure handling | All failures emitted as typed events (`*_FAILED`, `RETRY_BUDGET_EXHAUSTED`, `ROOT_CAUSE_ANALYZED`); never exceptions crossing boundaries |
| **Correlation ID Propagation** | Every event handler | `correlation_id` flows from root event to all descendants; `causation_id` = direct cause `event_id` |
| **Health Check Polling** | Component health | LifecycleManager polls `healthCheck()` every 30s (configurable); 3 consecutive failures = DEGRADED/FAILED |

## 6. Reference Implementation Boundary

### 6.1 System Boundary

**Source:** Part 1 §1.6.1, Part 3 §3.1
**Status:** EXISTING

**Requirement:** The Hermes Kernel is the system boundary for AI-OS. All Core Components and Core Managers MUST be owned and managed by the Hermes Kernel.

**Implementation Meaning:** The implementation MUST provide a HermesKernel class that owns and manages kernel entities. The exact composition of Core Components and Core Managers depends on which authoritative definition is selected per CONFLICT-CC-01 and CONFLICT-CM-01.

**Constraint:** No other component may instantiate, own, or manage Core Components or Core Managers.

### 6.2 Internal Implementation Boundary

**Source:** Part 1 §1.6, Part 3 §3.2, Part 4 §4.2
**Status:** EXISTING

**Requirement:** Internal to the kernel, there MUST be clear ownership and dependency boundaries.

**Implementation Meaning:** The implementation MUST preserve:
- Kernel-Owned Entities — Core Components, Core Managers, Services
- Kernel-Managed Lifecycle — Phased initialization and shutdown
- Service Registry — Service discovery and dependency management

**Constraint:** Cannot bypass ServiceRegistry for service discovery; cannot instantiate Core Components outside kernel.

### 6.3 External Integration Boundary

**Source:** Part 0 §0.5.2, Part 8 §8.1
**Status:** EXISTING

**Requirement:** Extension points MUST be governed and controlled.

**Implementation Meaning:** The implementation MUST provide:
- Extension mechanisms for custom events, skills, MCP transports, consensus algorithms
- Extension point validation and governance
- Version compatibility management for extensions

**Constraint:** Extensions MUST follow Part 0 §0.5.2 extension contracts; no unrestricted plugin systems.

### 6.4 Trust Boundary

**Source:** Part 14 §14.2, Part 14 §14.3, Part 4 §4.7
**Status:** EXISTING

**Requirement:** Security boundaries MUST be enforced.

**Implementation Meaning:** The implementation MUST preserve:
- Authentication boundary (SecurityManager)
- Authorization boundary (SecurityManager)
- Trust boundary (SecurityManager §4.7.9)

**Constraint:** Cannot bypass SecurityManager for authorization; must enforce trust levels.

### 6.5 Data Boundary

**Source:** Part 3 §3.4, Part 4 §4.4–4.6, Part 6 §6.3
**Status:** EXISTING

**Requirement:** State ownership must be clearly defined and enforced.

**Implementation Meaning:** The implementation MUST preserve:
- StateManager — Kernel runtime state authority
- StorageManager — Persistent storage governance
- MemoryManager — Memory types management

**Constraint:** No component may bypass StateManager for state mutations; all state ownership must be preserved.

### 6.6 Execution Boundary

**Source:** Part 4 §4.3, Part 4 §4.6, Part 4 §4.7
**Status:** EXISTING

**Requirement:** Execution boundaries MUST be preserved.

**Implementation Meaning:** The implementation MUST preserve:
- EventBus — Sole communication substrate
- LifecycleManager — Kernel lifecycle authority
- WorkflowManager — Workflow execution authority

**Constraint:** Cannot introduce new execution substrates; EventBus MUST remain sole communication mechanism.
